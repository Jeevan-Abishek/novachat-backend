How a message travels

One message, four hops, zero delay

Every send follows the same reliable path — no matter which region or instance answers the request.

1

Client sends

Message hits Nginx over a sticky WebSocket connection.

2

Instance receives

One of three Socket.IO nodes accepts and validates the payload.

3

Redis fans out

Pub/sub broadcasts the event to every other connected instance.

4

Peers receive

MongoDB persists it; every recipient sees it appear instantly.

FAQ

Questions, answered

How does NovaChat scale across regions?
Each region runs its own Nginx-fronted Socket.IO cluster. A shared Redis pub/sub layer keeps presence and message events synchronized across every instance, so users on different servers still see each other in real time.
Is my data encrypted?
Yes. Traffic is encrypted in transit over HTTPS/WSS, and messages are encrypted at rest. Enterprise plans support customer-managed keys.
Can I self-host NovaChat?
Enterprise customers can deploy the full stack — Node.js, MongoDB replica set, Redis, and Nginx — inside their own VPC with our Docker images.
What happens if a server instance goes down?
Nginx health checks detect the failure within seconds and reroute connections to healthy instances, while Redis ensures no message state is lost mid-flight.
